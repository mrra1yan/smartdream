## Implementation Plan (7 files, সব feature unchanged)

### 1. `src/lib/autolike.ts` — `getAutoLikeStatus()` column narrowing

**Current**: `profiles.select("*")` — fetches 28 columns
**Change**: `profiles.select("auto_like_enabled, auto_like_paused, auto_like_model, auto_like_expiry, auto_like_quota, auto_like_used, free_autolike_until, auto_like_paused_remaining_minutes, free_autolike_paused_remaining_minutes")`
**Impact**: 68% data reduction per call. Called every ~20s during Auto-Like + on every premium page load + every autolike-button mount.

### 2. `src/app/actions/chart.ts` — `getWeeklyLikeStats()` column narrowing

**Current**: `likes.select("*")` — fetches 7 columns (id, liker_id, link_id, receiver_id, is_anonymous, is_boosted_like, created_at)
**Change**: `likes.select("liker_id, receiver_id, created_at")`
**Impact**: 57% data reduction per row. For active users with 100+ likes/week, this saves significant bandwidth.

### 3. `src/components/home-stats-client.tsx` — polling interval increase

**Current**: `setInterval(..., 60_000)` — every 60 seconds
**Change**: `setInterval(..., 180_000)` — every 3 minutes
**Impact**: 67% fewer `get_my_stats` RPC calls. Realtime subscription already covers live updates; polling is just a safety net.

### 4. `src/components/profile-stats-client.tsx` — polling interval increase

**Current**: `setInterval(..., 60_000)` — every 60 seconds
**Change**: `setInterval(..., 180_000)` — every 3 minutes
**Impact**: Same as above. Also: add `document.visibilityState === 'hidden'` check to skip polling when tab is hidden.

### 5. `src/components/feed.tsx` — revalidation interval increase

**Current**: `REVALIDATE_INTERVAL_MS = 120_000` (2 minutes)
**Change**: `REVALIDATE_INTERVAL_MS = 300_000` (5 minutes)
**Impact**: 60% fewer feed RPC calls. `likes_count` changes are cosmetic — users see live stats via realtime anyway.

### 6. `src/lib/admin.ts` — narrow admin query columns

**Changes**:
- `getPendingUsers()` (line 66): `select("*")` → `select("id, public_id, first_name, last_name, phone, email, role, status, created_at, referred_by")`
- `getAllUsers()` (line 112): same column narrowing
- `searchUsers()` (line 129): same column narrowing

### 7. `src/lib/super-admin.ts` — narrow super-admin query columns

**Changes**:
- `getEliteUsers()` (line 14): `select("*")` → `select("id, public_id, first_name, last_name, phone, email, role, status, is_elite, is_boosted, created_at")`
- `getAllUsersForSuper()` (line 179): same column narrowing
